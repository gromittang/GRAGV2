# Iteration 2 Bug Log

> 记录 Iteration 2 中发现的所有 hybrid 管线问题。

## Bug #1: RAG dispatch — checkpointer config 缺失

**状态**: ✅ Fixed (`8b39f23`)

**复现**: 输入 "查询下库存前10的商品数量，然后看应该怎么做出库操作" → RAG 步骤报错：
```
dispatch 失败: Checkpointer requires one or more of the following 'configurable' keys: []
```

**根因**: `dispatch_to_rag()` 调用 `graph.ainvoke()` 时未传 `config` 参数。RAG graph 编译时带了 `MemorySaver` checkpointer，LangGraph 要求 `ainvoke(config={"configurable": {"thread_id": "..."}})`。

**修复**: `dispatch.py` 引入 `get_langgraph_config()`，传入 `config=get_langgraph_config(session_id="orchestrator_rag")`。

---

## Bug #2: 前端 axios 超时 30s 不够

**状态**: ✅ Fixed (`39f4129`)

**复现**: 输入任意 hybrid 问题 → 前端报 "请求失败：timeout of 30000ms exceeded"。

**根因**: `api/index.js` 中 axios 全局 `timeout: 30000`。Hybrid 管线 NL2SQL (~30s) + RAG (~10s) + Synthesis (~3s) ≈ 45s，超过 30s。

**修复**: `api/orchestrator.js` 单独设置 `timeout: 120000`。

---

## Bug #3: NL2SQL ambiguous column

**状态**: 📋 Backlog (非 orchestrator 范围)

**复现**: 输入 "查询下库存前10的商品数量" → NL2SQL 步骤报错：
```
Column 'plu_code' in field list is ambiguous
```

**根因**: `query_agent.py` 生成的 SQL 在 JOIN 时引用 `plu_code` 未指定表名前缀。

**处置**: 属于 NL2SQL agent 模块范围，记录为 Iteration 3 backlog。非 orchestrator 问题。

---

## Bug #4: Windows 端口 8812 被 Hyper-V 保留

**状态**: ✅ Fixed (`c245be9`)

**复现**: 后端启动时 bind `0.0.0.0:8812` → "以一种访问权限不允许的方式做了一个访问套接字的尝试"。

**根因**: Hyper-V Host Network Service 保留端口段 8807-8906。

**修复**: 全项目端口切换到 8912（紧邻保留段外）。
