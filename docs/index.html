核心能力

MCP Data Copilot + RAG 问答 + NL2SQL + PM 方案工作室，覆盖仓库日常工作的完整 AI 辅助链

🔌

MCP Data Copilot

Phase 2 核心升级：基于 MCP 2024-11-05 Streamable HTTP 协议的预构建查询。15 个 Tool 覆盖库存/商品/入库/出库/分析五大领域，封装预编译 SQL + 安全校验 + 参数验证。

三级回退链：MCP Tool → Local NL2SQL → QueryAgent，CircuitBreaker 自动熔断故障服务，业务错误不影响熔断计数。

🚦

统一查询网关

DataQueryGateway 是所有数据查询的唯一入口。MCP eligibility 纯规则判断（零 LLM 开销，含 Unicode 安全的正则实体识别），失败时自动回退到下一级 Executor。

查询追踪：每次查询生成三层 Trace JSON（leader/ops/debug），LogsPage 可视化展开。

🧠

智能问答 (RAG)

LangGraph 编排的多阶段检索管线：Query 改写 → BM25 + 向量双路并行检索 → RRF 融合排序 → Cross-Encoder 重排序 → DeepSeek LLM 流式生成。

图片理解：文档图片自动提取并展示，AI 可结合图片内容回答。

📚

文档管理 + 智能分块

支持 Word / PDF / TXT 上传解析，图片自动提取保留原始顺序。

行业自适应分块：5 档行业预设（通用/WMS/医疗/法律/金融），chunk_size 300~1000 + chunk_overlap 50~200 按行业自动切换。IMG token 占位符法保护图片标记不被切断。

🎯

PM方案工作室

四阶段结构化方案设计：问题定义 → 方案分析 → 方案细化 → PRD 生成。每个阶段可独立确认、回溯、重新生成。

时间轴导航：顶部 TimelineStepper 替代传统步骤条，直观展示阶段进度与状态。

🔭

全链路可观测性

两层零外部依赖：Loguru 结构化日志（按日轮转 JSON lines）+ 本地 Trace/Span 系统（异步批量写入 JSONL）。LangChain Callback 自动捕获每个 Graph 节点的 Span。

Token 用量全量捕获：6 个 LLM 调用点全量记录 token usage。

🔌 MCP Data Copilot — 预构建 Tool 替代 LLM 自由生成 SQL

传统 NL2SQL 依赖 LLM 自由生成 SQL，存在准确率不稳定、prompt 维护成本高、复杂查询不可控等问题。 本系统引入 MCP Data Copilot Server（独立部署 :8922），提供 15 个只读预构建 Tool， 每个 Tool 封装预编译 SQL + 安全校验 + 参数验证，从根本上消除了 LLM 生成 SQL 的质量波动。

CircuitBreaker 区分故障类型：仅服务级故障（连接失败/超时/认证错误）计入断路器计数，业务错误（Tool 选择失败/参数错误）不计入——它们反映查询本身的问题而非服务健康。 保守回退策略：未知错误默认允许回退，避免因错误分类遗漏导致查询完全失败。

行业 chunk_size chunk_overlap top_k BM25 设计理由

finance 6001006✅ 介于通用和 WMS 之间

IMG 占位符保护法： 分块前 [IMG]...[/IMG] → __IMG_TOK_N__ → SentenceSplitter 切分 → 分块后还原。 占位符作为原子文本不会被切断，保证图片标记始终完整保留在某个 chunk 中。 chunk_overlap ≈ chunk_size × 15~20%，小块用小重叠避免冗余，大块用大重叠补偿信息密度。

📊 Layer 1: 结构化日志
  • Loguru 控制台彩色 + JSON lines 文件
  • 按日轮转，普通日志 30 天 / Error 90 天
  • ContextVar 绑定 trace_id 到每条日志
🔎 Layer 2: Trace/Span
  • 异步批量写入 JSONL，每批 10 条或 1 秒刷新
  • LangChain Callback 自动捕获 Graph 节点 Span
  • 支持 sync + async 双模式 TraceContext

查询追踪三层视图： 每次查询生成结构化 trace_json → 存储在 query_history 表 → LogsPage "查询追踪" Tab 可视化展开。 leader_view（一句话概览）→ ops_view（断路器状态/回退路径/trace_id）→ debug_view（SQL/Tool 选择详情/时间线分解）。 一次查询满足管理、运维、开发三个角色的信息需求。

快速开始

三步部署，从零到拥有仓库智能知识库

1

Docker 启动

克隆项目，一键启动 Docker 容器

# 克隆项目
git clone https://github.com/gromittang/WMSRAGV2.git
cd WMSRAGV2

# 一键启动（前端 :8812 / 后端 :8912 / MCP :8922）
docker-compose up -d
2

配置 API Key + MySQL + MCP

编辑环境变量，配置 LLM API、业务数据库和 MCP Server

# 编辑 backend/.env 文件
DEEPSEEK_API_KEY=your_api_key_here

# MySQL配置（Data Copilot 业务数据源）
MYSQL_HOST=localhost
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=your_password
MYSQL_DATABASE=wms

# MCP Data Copilot 配置（Phase 2）
MCP_ENABLED=true
MCP_BASE_URL=http://localhost:8922
MCP_API_KEY=gk-xxxx
MCP_TIMEOUT=60.0

# LLM Provider（可选：deepseek/openai/anthropic）
LLM_PROVIDER=deepseek
3

访问系统

打开浏览器，开始使用所有模块

# 访问前端界面
http://localhost:8812

# 数据查询:     /query       MCP Tool + NL2SQL 双路径
# 智能编排:     /orchestrator 跨模块混合管线
# 智能问答:     /chat        知识库 RAG 对话
# PM工作室:     /pm-studio   方案设计四阶段
# 知识库管理:   /knowledge   文档上传与索引
# 查询追踪:     /logs        查询追踪 Tab
# 系统设置:     /settings    模型与连接配置

API 参考

核心接口前缀 /api/v1，默认端口 8912（前端代理），共 15+ 端点

方法 路径 说明
POST /api/v1/query/ DataQueryGateway — MCP Tool → NL2SQL → 兜底 三级回退
POST /api/v1/query/execute 直接执行 SQL（带安全校验 + 自动 LIMIT）
GET /api/v1/query/schema 获取完整数据库 Schema（514 表 / 7904 字段）
GET /api/v1/query/schema/search 关键词搜索表/字段（SchemaBrowser 搜索框）
GET /api/v1/query/history/{session_id} 获取会话查询历史（含 trace_json 三层追踪）
POST /api/v1/orchestrator/query 智能编排 — Hybrid Router → Planner → Executor
POST /api/v1/chat/stream SSE 流式智能问答（Markdown 渲染 + 图片展示）
POST /api/v1/docs/upload 上传文档（Word / PDF / TXT / MD，最大 10MB）
GET /api/v1/docs/list/{page}/{size} 分页获取文档列表（按知识库过滤）
POST /api/v1/docs/knowledge 创建知识库（可选行业类型，影响分块策略）
GET /api/v1/vector-admin/health/{kb_id} 向量库健康检查（SQL vs ChromaDB 差异）
POST /api/v1/vector-admin/rebuild/{kb_id} 重建向量索引
POST /api/v1/pm-solution/sessions 创建 PM 方案会话（四阶段）
GET /api/v1/logs/list 获取日志列表（含查询追踪数据）
GET /health 健康检查
